# DuoFolio · 降价实验操作单(2026-11-13)

> 目的:测试价格弹性 + 用「限时半价」给 featuring nomination 添一个"newsworthy"钩子。
> 价格现状:$6.99(价格点位 12 / Tier 7)。**全部价格改动在 ASC 网页「定价与供应」页操作,不触发审核。**

---

## 0. 时机(重要)

| 前提 | 原因 |
|---|---|
| 先完成 conversion-fix.md 的 A-H 手贴 | 半价流量进来时,产品页必须已经在转化。否则白烧流量 |
| en 描述/副标题上线 ≥3 天后再降价 | 让自然流量先跑一版基线,否则分不清涨价跌价效应 |
| nomination 提交后立刻降价 | nomination 表单里有「促销计划」字段,降价时间线要能对上 |

**不要的时机**:App 内没有评分时降价只对流量转化有效、对排名助推弱(评分是排名权重最大的因子)。

## 1. 降价方案:一次性「新品半价」$3.99

| 项 | 值 |
|---|---|
| 价格点位 | 12 ($6.99) → **点位 8 ($3.99)**(US;各区分自动跟随等值) |
| 生效方式 | ASC 网页 → 定价与供应 → 未来价格日程(选立即) |
| 周期 | **挂满整个 featuring 评审窗口(3-6 周)**,期间不回涨 |
| 回涨 | featuring 结果落地后,涨回 $6.99 前先看数据(见 §4) |

为什么是 $3.99 不是 $2.99/$1.99:
- $3.99 在 Books 工具类仍是"低决策"价位,但保住单价收入(每单 $2.77 vs $1.39)
- 低于 $2.99 的 app 在美区 Books 类容易被归类为"廉价工具",反伤 featuring 印象
- 半价话术成立:"50% off launch sale" 比 "temporary price drop" 更像策划行为

## 2. 配套动作(降价同一天做)

1. **Promo Text 更新**(免审核即时生效,170 字符)——conversion-fix.md §E 的降价版:
   - en: `🎉 50% off launch sale — $6.99 → $3.99. Pure local reading for iPhone Duo: unfold into a two-page book, auto-bookmark on close. No account, no cloud.`
   - zh-Hans: `🎉 新品半价 ¥45 → ¥25(限时)。iPhone 折叠屏双页阅读:展开成书,合盖自动书签,纯本地不上云。`
   - ja / zh-Hant:conversion-fix.md §E 模板里替换价格数字即可
2. **X 发一条降价帖**(可选,文案你自己写):截图=展开双页图,一句 "50% off launch sale" + 链接。不投广告。

## 3. 观测窗口(降价后 D+1 / D+3 / D+7)

数据通路:`/tmp` 脚本范式 `duofolio_v6.py`(ASC API 日级下载)。观测项:

| 指标 | 基线(6 周均值) | 关注点 |
|---|---|---|
| 日下载 | 0.14 份/天 | D+3 内应有 2-5 倍跳变(降价信号) |
| PV→下载率 | 0.45% | 降价后应在 15-30%(低于 10%=转化层没修好,先回工单) |
| impressions | 132/天 | 降价本身不推 impressions,排名动了才会涨 |

## 4. 回涨决策树(D+7 数据说话)

```
D+7 累计下载 ≥ 25 份 且 PV→DL ≥ 20%
  → 转化层修复成立。回涨 $6.99,重评 featuring 进度
D+7 累计 10-25 份
  → 半价 $3.99 再挂 2 周冲刺评分(每单都问一次评分的时机),之后回涨
D+7 累计 < 10 份 且 PV→DL < 10%
  → 问题不在价格在产品页(截图/首屏文案),回到 conversion-fix.md 重排 D 节
```
